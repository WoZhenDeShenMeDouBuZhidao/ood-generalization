Goal: reduce runner and loss duplication before scaling to more methods and
datasets.

  - `CrossEntropyCELoss`

  - `LLMAttributionAlignedCELoss`

  baseline without any LLM prior.
- Consolidated all method entrypoints into `run_experiment.py`.
- `run_experiment.py` now selects method with `--method`:
  - PyTorch path: `mlp_ce`, `gradient_regularized_ce`, `fitce`, `laat`,
    `llm_select`
  - sklearn path: `linear`, `llm_lasso`

  `archive/runners/`:

  - `run_fitce.py`
  - `run_laat.py`
  - `run_llm_select.py`
  - `run_linear.py`
  - `run_llm_lasso.py`

LLM-Lasso implementation check:

- Checked the official `pilancilab/LLM-Lasso` reference implementation.
- The official code uses penalty factors with a weighted Lasso solver
  (`adelie` / `grpnet` style path).
- The project implementation keeps LLM-Lasso in the sklearn path and applies the
  same weighted-L1 idea through feature rescaling before L1 logistic regression.
  This is closer to the official method than adding a PyTorch loss.
