執行方式：

| setting | ID | OOD MEAN | OOD WORST |
| --- | ---: | ---: | ---: |

第一輪結論：

- synthetic 的最佳 loss 超參數可以轉移到 ACS
- 但前提不是 GPT-based ranking，而是更接近資料實證的 leave-one-out ranking
- 只改 ranking、不改 suppression set 不夠：
  - `leave_one_out_all_positive = 0.7015`
- suppression 也不能太強：
  - `leave_one_out_top5 = 0.7059`
- 目前最佳平衡點是：
  - top-7 positive
  - suppress `OCCP`、`COW`、`RAC1P`

### Strategy Pivot After User Feedback

使用者明確補充：

- 專案的真正目標不是依賴 leave-one-out 找 ranking
- 而是：
  - 給定 dataset 與 feature 資訊
  - 讓 LLM 輸出 ranking
  - 再根據 LLM ranking 決定 `FEATURE_LOSS_WEIGHTS`
- leave-one-out 雖然有診斷價值，但不能當主要流程，因為成本太高

因此策略更新為：

- 停止擴大 leave-one-out 實驗
- 保留本輪結論作為診斷證據：
  - GPT-based ranking 與目前有效 ranking 有明顯差距
- 下一步主線改成：
  - 優化 `prompt.md`
  - 讓模型除 ranking 外，額外輸出：
    - 從哪一個 rank 之後可能進入 spurious / unstable 區段
  - 再依這個輸出測試更 coarse 的 weight grouping

對應更新：

- 已重寫 `prompt.md`
  - 保留 dataset 名稱可填空欄位
  - 要求模型自行搜尋資料集資訊
  - 要求輸出：
    - feature ranking
    - `spurious_start_rank`
    - per-feature importance / spurious-risk scores
    - 可直接映射到 `FEATURE_LOSS_WEIGHTS` 的 grouping 建議
