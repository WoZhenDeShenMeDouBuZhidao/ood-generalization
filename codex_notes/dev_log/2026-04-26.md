# Dev Log: 2026-04-26

## Why Train-Std Scaling Partially Fixes Grad L2 and SHAP

The ACSIncome issue is a feature-unit problem.

`FeatureImportanceTargetCELoss` originally regularized raw-input sensitivity:

```text
raw gradient_j = d logit / d x_j
```

This quantity depends on the unit of `x_j`. If one feature has a much larger numeric range,
the model can use that feature with a very small raw-unit gradient. For ACSIncome, `OCCP`
has train-set std around `2405`, while `AGEP` has std around `13.65`. A one-unit change in
`OCCP` is tiny relative to the actual variation of `OCCP`; a one-unit change in `AGEP` is
much more meaningful.

SHAP is closer to a distribution-scale quantity. It measures how much model output changes
when a feature varies across realistic data values. Therefore a feature can have:

```text
small raw d logit / d x_j
large output movement across the observed feature distribution
large mean |SHAP|
```

This is exactly why the unscaled ACSIncome regularizer could show tiny `Feature Grad L2`,
while SHAP was still dominated by `OCCP`.

The scale-aware correction uses train-set standard deviation as a unit conversion:

```text
x_j = mean_j + std_j * z_j
d logit / d z_j = d logit / d x_j * std_j
```

So instead of asking "how sensitive is the model to one raw unit of this feature?", the loss
asks "how sensitive is the model to one train-standard-deviation movement of this feature?"

Implementation:

```text
scaled_grad_j = raw_grad_j * train_std_j
grad_l2_j = mean(scaled_grad_j ** 2)

scaled_weight_abs_j = abs(first_layer_weight_j) * train_std_j
```

This partly fixes the diagnostics because:

- Large-scale features such as `OCCP` can no longer hide behind tiny raw-unit gradients.
- `Feature Grad L2` moves back to a readable scale, similar to what dataset standardization
  did, without changing the model input distribution.
- The regularizer's notion of feature importance becomes closer to SHAP's notion: output
  sensitivity over realistic feature variation.
- First-layer weight importance also becomes more comparable across raw feature units.

It is only a partial fix because std scaling corrects feature units, not feature stability
or causal validity.

Remaining reasons SHAP can still become uneven:

- If the target ranking gives high mass to an unstable feature such as `OCCP`, the corrected
  loss now gives that target real force instead of letting raw-scale artifacts mute it.
- Std captures only second-moment scale. It does not model categorical semantics, sparsity,
  skew, code distance, or state-specific distribution shift.
- SHAP is evaluated after training on the learned nonlinear model and validation distribution;
  the training regularizer only constrains gradient and first-layer-weight proxies.
- The loss balances CE accuracy against the feature prior. CE can still prefer a feature if
  it is predictive in the training state.

Current empirical read:

- The small-grad problem is fixed: plotted `Feature Grad L2` is around `1e-3` per feature
  rather than around `1e-7` total.
- SHAP is improved but not fully solved:
  - repeat 1/2 validation PR SHAP no longer show single-feature dominance by `OCCP`;
  - repeat 3 still has `OCCP = 0.1656` versus `WKHP/SCHL = 0.0776`, so seed instability
    remains.

Conclusion:

`importance_scale="train_std"` is the right minimal correction for raw feature-unit mismatch.
It makes the feature-importance regularizer scale-aware and more aligned with SHAP, while
preserving raw-input CE performance. However, it does not by itself guarantee stable OOD
feature usage. The next likely lever is the target prior itself, especially reducing the
target mass assigned to `OCCP`.
