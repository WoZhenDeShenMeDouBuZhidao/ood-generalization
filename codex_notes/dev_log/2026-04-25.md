# Dev Log: 2026-04-25

使用者指出 2026-04-23 的 ACSIncome train-stat standardization 雖然解決了
`Feature Grad L2` 過小與 SHAP 被 `OCCP` 極端主導的診斷問題，但會讓
ID / OOD MEAN / OOD WORST accuracy 都下降。

### Diagnosis: Standardize Diagnostics Without Standardizing Model Inputs

2026-04-23 的核心診斷仍成立：

- raw ACSIncome feature scale 差異很大。
- `FeatureImportanceTargetCELoss` 原本用 raw input unit 計算
  `d logit / d x_j` 與 first-layer weight importance。
- SHAP 則反映 feature 在實際資料分布中的輸出變動。
- 因此 `OCCP` 這類大尺度 feature 即使 raw-unit gradient 很小，仍可能主導 SHAP。

但把整個 dataset standardize 會改變模型看到的輸入分布與 optimization geometry；
這可以修正 attribution diagnostic，卻不是最小干預。

本輪改成：

- 保留 raw ACSIncome inputs 給模型。
- 僅在 feature-importance loss 內，把 gradient / first-layer-weight importance
  換算成「每一個 train-set standard deviation 的輸出敏感度」：
  - gradient importance: `grad_j * train_std_j`
  - first-layer weight importance: `abs(weight_j) * train_std_j`
- 也就是用 `d logit / d z_j` 的尺度做 regularization，其中
  `x_j = mean_j + std_j * z_j`。

這樣的目標是同時保留 raw-input CE accuracy，並讓 regularizer 與 SHAP 的
feature-variation notion 對齊。

### ACSIncome Scale-Aware GPT Ranking Experiment

Fixed setting:

- `MLP`
- train/val state: `PR`
- OOD tests: same 46 states as `run_acsincome.py`
- fixed seeds: `[9803, 38224, 8113, 4854, 98825]`
- `LOSS_NAME="feature_importance_target_ce"`
- `FEATURE_LOSS_WEIGHTS` from 2026-04-14 GPT ranking / scores:
  - `SCHL=9`, `WKHP=8`, `OCCP=8`, `AGEP=7`, `COW=6`,
    `MAR=5`, `RELP=4`, `POBP=3`, `SEX=2`, `RAC1P=1`
- `REG_SCALE=0.5`
- `reweighting=True`
- `grad_scale=2.0`
- `weight_scale=3.0`
- `suppress_scale=6.0`
- `target_power=1.0`
- `importance_scale="train_std"`
- raw dataset:
  - `resampling=False`
  - `standardize=False`
- run on `cuda:0`, plotting and SHAP monkeypatched off for metric screening.

Result:

| setting | ID | OOD MEAN | OOD WORST |
|---|---:|---:|---:|
| CE reweighting baseline from 2026-04-19 | 0.8490 | 0.7580 | 0.7232 |
| FeatureImportanceTargetCELoss raw, no scale-aware correction | 0.8421 | 0.7599 | 0.7216 |
| FeatureImportanceTargetCELoss + dataset standardization | 0.8034 | 0.7538 | 0.7172 |
| FeatureImportanceTargetCELoss + scale-aware importance | 0.8591 | 0.7602 | 0.7170 |

Interpretation:

- Scale-aware importance fixes the main downside of dataset standardization:
  ID accuracy no longer collapses, and is higher than the CE reweighting baseline.
- OOD MEAN is also slightly higher than CE reweighting.
- OOD WORST still underperforms CE reweighting by about `0.0062`.
- Therefore this is a useful direction, but it does not yet fully satisfy
  "exceed CE loss" under all three metrics.

### Next Candidate

The remaining gap is likely not raw feature scaling anymore. The current GPT ranking gives `OCCP`
high target mass. After scale-aware correction, that target now has real force, so worst-state
accuracy may still be hurt if `OCCP` is unstable across the worst OOD states.

Recommended next screen:

- keep raw inputs and `importance_scale="train_std"`
- compare GPT weight variants that reduce only `OCCP` target mass without leaving the GPT route:
  1. `gpt_3group_321` from `archive/acsincome/gpt_acsincome.json`
  2. GPT score weights but set `OCCP=6` instead of `8`
  3. GPT score weights but set `OCCP=4` and keep all other GPT ranks unchanged

The decision criterion should remain the CE reweighting baseline:

- must keep `ID >= 0.8490`
- must keep `OOD MEAN >= 0.7580`
- should recover `OOD WORST > 0.7232`
