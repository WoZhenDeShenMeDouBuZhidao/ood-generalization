## Synthetic OOD FITCE Attribution Target Quick Check

Goal: quickly test whether FITCE should regularize the positive-class logit
gradient or the binary decision-margin gradient.

Settings:

- Dataset: `synthetic_ood/simple`.
- Prior: current oracle prior
  `causal_continuous_1p25=2`, `causal_continuous_0p75=1`, `spurious_continuous_2p25=0`, `noise_continuous_1/2/3=0`.
- `REPEAT=3`, `PATIENCE=100`, `LR=1e-4`, `TRAIN_BATCH=256`,
  `EVAL_BATCH=2048`.
- Plots: `--plot-curve --plot-shap`, validation SHAP only.
- SHAP sample size: `500`.
- CPU thread limit for each process:
  `OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 NUMEXPR_NUM_THREADS=1`.
- FITCE fair grad-only settings: `loss_lambda=1`, `loss_alpha=1`
  (`grad_scale=1`, `weight_scale=0`), `suppress_bound=0`,
  no target-distribution power transform (old `target_power=1` equivalent),
  `importance_scale=none`.
- LAAT uses the same `REG_SCALE` values.
- Code change for the margin run: `src/loss.py` now uses
  `logits[:, 1] - logits[:, 0]` as the attribution scalar instead of
  `logits[:, 1]`.

Positive-logit vs margin-gradient definition:

- Positive-logit attribution computes input gradients of `logits[:, 1]`.
  It measures which features increase the positive-class logit alone.
- Margin attribution computes input gradients of `logits[:, 1] - logits[:, 0]`.
  It measures which features change the binary decision margin / log-odds.
- Binary softmax classification depends on the relative margin, not the absolute
  positive logit. A feature can affect `logit_0` and therefore the class
  decision even when `d logit_1 / d feature` is small. This is why margin
  gradients are more faithful to actual binary feature usage.
- In multiclass settings, the analogous general form would be a true-class
  margin such as `logit_y - logsumexp(logits_except_y)` or
  `logit_y - max(logits_except_y)`.

Selection score is
`Acc OOD Mean + Acc OOD Worst + F1 OOD Mean + F1 OOD Worst`.

## Synthetic OOD Per-Sample Gradient Normalization Check

Goal: test whether attribution regularizers should normalize each sample's
feature-gradient vector first, then average the loss, instead of the current
batch-mean-gradient then normalize approach.

Definitions:

- Batch-normalized gradient distribution:
  `grad_l2 = mean_batch(grad^2)`, then
  `grad_probs = grad_l2 / sum_features(grad_l2)`.
- Sample-normalized gradient distribution:
  `sample_grad_probs = grad_i^2 / sum_features(grad_i^2)` for each sample,
  then the FITCE CE / LAAT MSE loss is averaged across samples.
- Sample-normalized is closer in spirit to local attribution matching, but it
  changes the regularization target substantially.

Settings are the same as the previous section:

- `REPEAT=3`, `PATIENCE=100`.
- Attribution scalar: binary logit margin `logits[:, 1] - logits[:, 0]`.
- SHAP sample size: `500`.
- CPU thread limit per process.

## Synthetic OOD FITCE Gradient Softmax Temperature Sweep

Goal: improve the FITCE grad term by replacing direct sum normalization with
temperature-controlled softmax over log gradient signal:

`grad_probs = softmax(log(mean_batch(grad^2) + eps) / tau)`

This keeps `tau=1` equivalent to the previous sum-normalized FITCE baseline,
while allowing sharper (`tau<1`) or smoother (`tau>1`) gradient attribution
distributions.

Implementation:

- Added `--grad-prob-temperature` for FITCE.
- Default is `1.0`, matching the previous `grad_l2 / grad_l2.sum()` behavior.
- Curve diagnostics now use the same tau as the loss, so Grad Rank/Weight
  distances match the optimized distribution.

Settings:

- Dataset: `synthetic_ood/simple`.
- FITCE settings: `REG_SCALE=10`, `loss_lambda=1`, `loss_alpha=1`,
  `grad_scale=1`, `weight_scale=0`, `importance_scale=none`,
  `suppress_bound=0`, no target-distribution power transform.
- Ranking/prior: synthetic oracle `score_all` / `score`.
- `REPEAT=3`, `PATIENCE=100`, `LR=1e-4`.
- SHAP sample size: `500`.
- CPU thread limit per process.
- Comparison rows for MLP CE, nonnegative LAAT, and remove-spurious reuse
  previous results from this dev log.

## FITCE Target-Power Removal

`target_power` was removed from the active FITCE implementation and CLI after
the gradient-probability temperature sweep.

Reason:

- The removed target transform was
  `target_probs = normalize(feature_weight ** target_power)`.
- The current gradient transform is
  `grad_probs = softmax(log(mean_batch(grad^2) + eps) / tau)`, which is
  equivalent to normalizing `grad_signal ** (1 / tau)`.
- In the CE optimum, `grad_probs` is pushed toward `target_probs`, so
  `target_power` and `tau` both control how sharp the effective feature
  attribution distribution becomes.
- Keeping both parameters makes the optimization space harder to explain.
  It is cleaner to leave the LLM prior unchanged and calibrate the model-side
  gradient-to-probability mapping with `--grad-prob-temperature`.

Current FITCE target construction:

- Clamp feature weights to nonnegative values.
- Normalize directly to a target distribution.
- Apply `suppress_bound` after normalization when requested.
