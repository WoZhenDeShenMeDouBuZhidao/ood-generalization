## ACS Plain CE Baseline: BatchNorm Diagnosis

Goal:

- Explain why several binary ACS tasks had OOD WORST accuracy far below random accuracy
  under the train-state sweep baseline.
- Test whether the same raw feature value range issue previously observed in `acsincome`
  also appears in the other ACS tasks.

Procedure:

- Kept each task's confirmed `TRAIN_VAL_STATE` from the sweep above.
- Used `MLP + CrossEntropyLoss`.
- No resampling, no class reweighting, no standardization.
- Changed the MLP from the no-BatchNorm sweep baseline back to the default architecture:
  `Linear -> BatchNorm1d -> ReLU -> Linear`.
- Ran 5 seeds where feasible:
  `[9803, 38224, 8113, 4854, 98825]`.

5-seed OOD WORST before/after adding `BatchNorm1d`:

| task | TRAIN_VAL_STATE | no-BN OOD WORST | BN OOD WORST | delta |
|---|---:|---:|---:|---:|
| `acsemployment` | `SD` | 0.7061 | 0.7649 | +0.0588 |
| `acsemploymentfiltered` | `SD` | 0.6474 | 0.7062 | +0.0588 |
| `acshealthinsurance` | `MN` | 0.2214 | 0.7829 | +0.5615 |
| `acsincomepovertyratio` | `HI` | 0.3964 | 0.6330 | +0.2366 |
| `acsmobility` | `AK` | 0.6385 | 0.6624 | +0.0239 |
| `acspubliccoverage` | `CA` | 0.1339 | pending full 5-seed | pending |
| `acstraveltime` | `AZ` | 0.2255 | pending full 5-seed | pending |

Important budget note:

- The BN OOD WORST values in this table are from the full 5-seed/default-budget runs where
  feasible (`MAX_EPOCHS=5000`, `PATIENCE=500`).
- They should not be expected to exactly match the later `no reweight OOD WORST` values in
  the reweighting ablation section, which were re-run under the shorter same-budget
  ablation setting (`MAX_EPOCHS=800`, `PATIENCE=100`).
- Example: `acsemployment` is `0.7649` in the full BN diagnosis but `0.7643` in the
  same-budget reweighting ablation baseline.

Short screening for the two slow tasks:

- `REPEAT=1`, `MAX_EPOCHS=800`, `PATIENCE=100`.
- `acspubliccoverage`: no-BN 0.1339 from full sweep vs BN short OOD WORST 0.6288.
- `acstraveltime`: no-BN 0.2255 from full sweep vs BN short OOD WORST 0.4635.

Interpretation:

- Adding `BatchNorm1d` is the dominant fix for the pathological below-random OOD WORST
  behavior.
- The largest improvements are on `acshealthinsurance`, `acsincomepovertyratio`,
  `acspubliccoverage`, and `acstraveltime`, which supports the hypothesis that raw ACS
  feature scale / numeric code ranges were destabilizing the no-BN MLP.
- Going forward, the default `MLP` architecture should include `BatchNorm1d`; the temporary
  no-BN variant is only a diagnostic baseline.

Implementation:

- `src/mlp.py` now keeps `BatchNorm1d` as the default MLP architecture.
- Temporary `MODEL_KWARGS` / `USE_BATCHNORM` plumbing was removed after the diagnosis.

## ACS Plain CE Baseline: Reweighting And State-Feature Defaults

Goal:

- With `BatchNorm1d` fixed as the default MLP architecture, decide which other simple
  baseline fixes should become task defaults:
  - class reweighting
  - removal of raw state-specific code features

Procedure:

- Used each task's confirmed `TRAIN_VAL_STATE`.
- Used default `MLP` with `BatchNorm1d`, `CrossEntropyLoss`, no resampling, no standardization.
- Same-budget before/after runs:
  - `REPEAT=5`
  - `MAX_EPOCHS=800`
  - `PATIENCE=100`
  - seeds `[9803, 38224, 8113, 4854, 98825]`
- Reweighting was tested first.
- For remove-state experiments, reweighting was only used if it was effective for that task.
  Under this check, reweighting was not effective for the three state-feature tasks, so
  remove-state was run without reweighting.

Reweighting before/after OOD WORST:

These before/after values are same-budget ablation runs, not reused from the full BN
diagnosis table above.

| task | no reweight OOD WORST | reweight OOD WORST | delta | decision |
|---|---:|---:|---:|---|
| `acsemployment` | 0.7643 | 0.7623 | -0.0020 | no default reweighting |
| `acsemploymentfiltered` | 0.7080 | 0.6699 | -0.0381 | no default reweighting |
| `acshealthinsurance` | 0.7739 | 0.7035 | -0.0704 | no default reweighting |
| `acsincomepovertyratio` | 0.6216 | 0.6223 | +0.0007 | default reweighting |
| `acsmobility` | 0.6489 | 0.6071 | -0.0418 | no default reweighting |
| `acspubliccoverage` | 0.5915 | 0.4959 | -0.0956 | no default reweighting |
| `acstraveltime` | 0.4658 | 0.4623 | -0.0035 | no default reweighting |

Remove state-specific raw code features before/after OOD WORST:

| task | removed features | before OOD WORST | after OOD WORST | delta | decision |
|---|---|---:|---:|---:|---|
| `acshealthinsurance` | `ST` | 0.7739 | 0.7776 | +0.0037 | default remove |
| `acspubliccoverage` | `ST` | 0.5915 | 0.6648 | +0.0733 | default remove |
| `acstraveltime` | `PUMA`, `ST`, `POWPUMA` | 0.4658 | 0.4764 | +0.0106 | default remove |

Decisions:

- Keep reweighting disabled by default for all non-income ACS tasks except
  `acsincomepovertyratio`.
- Enable reweighting by default for `acsincomepovertyratio`, but treat the effect as weak
  because the OOD WORST gain is only +0.0007 in this same-budget check.
- Enable state-specific raw code removal by default for:
  - `acshealthinsurance`: remove `ST`
  - `acspubliccoverage`: remove `ST`
  - `acstraveltime`: remove `PUMA`, `ST`, `POWPUMA`
- Keep those three remove-state defaults without reweighting because reweighting hurt their
  OOD WORST.

Implementation:

- The non-income `run_acs*.py` files now directly fix each task's best setting instead of
  deriving experiment settings from environment variables.
- `run_acsincomepovertyratio.py` uses `LOSS_KWARGS={"reweighting": True}`.
- `run_acshealthinsurance.py` fixes `REMOVED_FEATURE_INDICES=[23]` to remove `ST`.
- `run_acspubliccoverage.py` fixes `REMOVED_FEATURE_INDICES=[16]` to remove `ST`.
- `run_acstraveltime.py` fixes `REMOVED_FEATURE_INDICES=[9, 10, 14]` to remove
  `PUMA`, `ST`, and `POWPUMA`.
- Other non-income ACS runners use `LOSS_KWARGS={"reweighting": False}` and
  `REMOVED_FEATURE_INDICES=[]`.
- The temporary `acs_tasks/run_config.py` experiment helper was removed.
