- 但 variance 仍偏大；第 5 次 repeat 掉到 `0.6733`
- 下一步較合理的方向：
  - 強化 suppressed features 的 weight penalty
  - 或設計 reg schedule，避免某些 seed 在後期回頭撿 spurious signal

使用者明確定義 perfect feature ranking 為：

- `causal_continuous_1p25 > causal_continuous_0p75 > noise > spurious_continuous_2p25`

本輪目標：

- 在 ranking 已知完全正確的前提下，分開研究：
  - `FEATURE_LOSS_WEIGHTS`
  - `REG_SCALE`
  - `LOSS_KWARGS`
- 只看這些超參數本身會如何影響 acc

固定設定：

- model: `MLP`
- loss: `FeatureImportanceTargetCELoss`
- dataset: `synthetic_ood`
- fixed model seeds:
  - `9803`

  - `ood_spurious_corr = -0.95`
  - `causal_continuous_1p25_strength = 1.25`
  - `causal_continuous_0p75_strength = 0.75`
  - `spurious_strength = 2.25`
- `TRAIN_BATCH = 256`
- `EVAL_BATCH = 2048`
- `LR = 1e-4`
- `PATIENCE = 40`
- `REPEAT = 5`
- `MAX_EPOCHS = 400`

baseline perfect-ranking weights：

- `causal_continuous_1p25 = 3.0`
- `causal_continuous_0p75 = 2.0`
- `noise_continuous_1/2/3 = 1.0`
- `spurious_continuous_2p25 = 0.0`

baseline loss kwargs：

- `grad_scale = 1.0`
- `weight_scale = 3.0`
- `suppress_scale = 6.0`
- `target_power = 1.0`

#### `FEATURE_LOSS_WEIGHTS` Sweep

| setting | OOD |
| --- | ---: |
| `3, 2, 1, 0` | 0.8717 |
| `30, 20, 10, 0` | 0.8717 |
| `6, 3, 1, 0` | 0.8702 |
| `6, 3, 0.5, 0` | 0.8614 |

結論：

- `FeatureImportanceTargetCELoss` 內部會把正權重 normalize 成 target distribution
- 所以只改絕對 scale、不改比例時，acc 幾乎完全不變
- 把 causal 與 noise 的差距拉大沒有帶來提升
- 反而把 noise 再壓低到 `0.5` 時，OOD 下降

#### `REG_SCALE` Sweep

| setting | ID | OOD |
| --- | ---: | ---: |
| `0.5` | 0.9480 | 0.8751 |
| `1.0` | 0.9427 | 0.8565 |
| `2.0` | 0.9395 | 0.8717 |
| `4.0` | 0.9363 | 0.8711 |

結論：

- 本輪最佳是 `REG_SCALE = 0.5`
- `REG_SCALE = 1.0` 反而是最差設定
- `2.0` 與 `4.0` 的 OOD 很接近，進一步加強 regularization 沒再帶來額外收益

#### `LOSS_KWARGS` Sweep

| setting | OOD |
| --- | ---: |
| `grad=1, weight=1, suppress=2, power=1` | 0.8726 |
| `grad=1, weight=1, suppress=6, power=1` | 0.8698 |
| `grad=1, weight=3, suppress=6, power=1` | 0.8717 |
| `grad=1, weight=3, suppress=6, power=0.5` | 0.8692 |
| `grad=1, weight=3, suppress=6, power=2` | 0.8648 |
| `grad=2, weight=3, suppress=6, power=1` | 0.8681 |

結論：

- 在 perfect ranking 前提下，`LOSS_KWARGS` 已沒有先前 imperfect-ranking 那麼敏感
- 弱一點的 regularization (`weight=1`, `suppress=2`) 已能達到接近最好的結果
- 單純把 `weight_scale`、`suppress_scale` 加大，不再像之前一樣明顯提升 OOD
- `target_power` 不論壓平 (`0.5`) 或拉尖 (`2.0`) 都略差於 `1.0`
- 把 `grad_scale` 提到 `2.0` 也沒有幫助

#### Representative Plot-backed Observations

用固定 seed `9803` 比較 `REG_SCALE = 0.5 / 1.0 / 2.0`：

- 三者都已把 `spurious_continuous_2p25_grad_prob` 壓到約 `0.004` 到 `0.008`
- 三者的 `weight_mass_on_suppressed` 也都維持在約 `0.076` 到 `0.085`
- OOD SHAP 前幾名都仍以 `causal_continuous_1p25`、`causal_continuous_0p75`、`noise` 為主，沒有明顯重新撿回 `spurious_continuous_2p25`

代表目前 perfect ranking 下的主要差異，不是有沒有成功 suppress spurious，而是：

- causal 與 noise 之間怎麼分配 importance mass
- 以及這種分配對 optimization / early stopping 的影響

另外比較 `3,2,1,0` 與 `6,3,0.5,0`：

- 後者確實把 `noise_continuous_1_grad_prob` 從 `0.1174` 壓到 `0.0430`
- 同時把 `causal_continuous_1p25_grad_prob` 從 `0.3807` 拉到 `0.5629`
- 但 OOD 並沒有更好，反而略降 (`0.8832 -> 0.8788`，固定 seed 代表性觀察)

目前總結：

- ranking 正確時，超參數空間明顯比之前平坦
- `FEATURE_LOSS_WEIGHTS` 的比例比絕對值重要
- 太積極地把 mass 往 causal 集中，不一定會提升 synthetic OOD
- 下一步若要繼續逼近 optimal，可能需要：
  - 改善 optimization dynamics
  - 或設計更細緻的 schedule / constraint
  - 而不是單純把同一組 loss 超參數繼續放大

結論：

- 在完全固定其他條件下，`target distribution` 版本確實優於 `pairwise ranking` 版本
- 平均 OOD 提升約 `+0.0152`

- `FeatureGradCELoss`

    - `causal_continuous_1p25 = 1.3211`
    - `causal_continuous_0p75 = 0.7472`

  - `spurious_continuous_2p25_grad_prob = 0.0007`

代表：

- `FeatureGradCELoss` 雖然能把 ranking 方向推對，但仍保留很強的 `spurious_continuous_2p25`
- 把 gradient ranking 轉成 target distribution 後，spurious gradient mass 幾乎被清掉

結論：

- `target distribution` 版本同樣優於單純的 weight ranking
- 平均 OOD 提升約 `+0.0116`

固定 seed `9803` 的 plot-backed 觀察：

- `FirstLayerWeightCELoss`
  - OOD SHAP 前三名：
    - `causal_continuous_1p25 = 1.2215`
    - `spurious_continuous_2p25 = 0.8230`
    - `causal_continuous_0p75 = 0.6542`

    - `causal_continuous_1p25 = 1.3627`

#### Overall Conclusion

- 對 gradient 與 first-layer weight 這兩條路徑，答案都一致：
  - `target distribution > pairwise ranking`
- 這個結果支撐後續報告邏輯：
  1. 先證明「ranking 轉成分配比例」本身有價值
  2. 再引入 `suppress_scale` 與 `target_power`
  3. 接著做 `FEATURE_LOSS_WEIGHTS` / `REG_SCALE` / `LOSS_KWARGS` / term ablation
