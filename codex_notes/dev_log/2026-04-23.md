### Diagnosis: Raw Feature Scale Mismatch

核心原因不是 `FeatureImportanceTargetCELoss` 在 ACSIncome 上完全失效，而是 ACSIncome loader 原本沒有做 feature standardization。

對照：

- `synthetic_ood/dataset.py`
  - `_standardize_with_train_stats(...)`
  - train / val / OOD test 都使用 train mean/std。
- `acsincome/dataset.py`
  - 原本直接把 Folktables raw numeric/categorical codes 餵進模型。

Interpretation:

- The loss regularizes input-gradient L2 per raw feature unit:
  - `d logit / d OCCP`
  - `d logit / d SCHL`
  - etc.
- SHAP reflects output movement across the feature distribution.
- For a large-scale feature like `OCCP`, a tiny raw-unit derivative can still create a large output movement because `OCCP` varies over thousands of units.
- Therefore the loss can appear to satisfy a small `OCCP_grad_prob`, while SHAP still reports `OCCP` as dominant.
- This also explains why synthetic does not show the same issue: synthetic inputs are standardized before training.

### Code Changes

Implemented optional ACSIncome standardization:

- `acsincome/dataset.py`
  - added `_fit_standardization_stats(...)`
  - added `_standardize(...)`
  - replaced split public loaders with `acsincome_load_data(...)`.
  - `acsincome_load_data(...)` now loads train / val / tests in one call.
  - when `standardize=True`, it fits train stats after the train/val split and applies them to train / val / tests.
- `src/main.py`
  - dataset dispatch now calls one dataset loader and receives `(train, val, tests)`.
  - `dataset_config` is printed with the run config.
- `synthetic_ood/dataset.py`
  - replaced split public loaders with `synthetic_ood_load_data(...)`.
  - synthetic arrays are now built once per run and returned as train / val / tests.
- `run_acsincome.py`
  - changed ACSIncome config to:
    - `DATASET_CONFIG={"resampling": False, "standardize": True}`

Default behavior remains backward-compatible: standardization is off unless `standardize=True`.
