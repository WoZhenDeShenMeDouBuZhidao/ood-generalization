# Real-World FITCE Train-Std Scaling on All 18 Datasets

## Goal

Evaluate each FITCE improvement on all 18 real-world datasets before returning
to Top-5 worst-dataset diagnosis. This screen extends the previous five-dataset
`importance_scale=train_std` result to the remaining 13 datasets and compares
the combined result with MLP CE and the preceding FITCE configuration.

## Old FITCE Versus TrainStd FITCE

The two FITCE variants use the same model, prior, optimizer, checkpoint rule,
class reweighting, and regularization strength. The only behavioral difference
in this comparison is `importance_scale`:

- **Old FITCE:** `importance_scale=none`. It constructs the feature signal from
  the class-balanced mean squared binary logit-margin gradient in raw input
  units.
- **TrainStd FITCE:** `importance_scale=train_std`. It multiplies each input
  logit-margin gradient by that feature's training-split standard deviation
  before computing the mean squared feature signal and alignment distribution.

Thus TrainStd makes the FITCE gradient target invariant to simple changes in
continuous-feature units. It does not standardize model inputs and does not
change the CE term. The later diagnostic-logging change that records raw CE and
raw gradient loss also leaves the optimized total loss unchanged.

## Protocol

- Datasets: all 18 real-world datasets; synthetic datasets are excluded.
- MLP CE, old FITCE, and TrainStd FITCE all use class reweighting `on`.
- `REPEAT=3`, seeds `9803`, `38224`, and `8113`; `PATIENCE=200`,
  `MAX_EPOCHS=5000`, `LR=1e-4`, train batch 256, and eval batch 2048.
- FITCE shared settings: GPT-5.4 semantic `rank/rank`, binary logit-margin
  gradient term only, `REG_SCALE=0.1`, `tau=2`, and no warmup.
- Checkpoint score: validation Balanced Accuracy + validation Macro-F1.
- ID Selection is ID Balanced Accuracy + ID Macro-F1.
- OOD Selection is BAcc OOD Mean + BAcc OOD Worst + Macro-F1 OOD Mean +
  Macro-F1 OOD Worst.
- No confidence interval is reported in this screen.

The 13 new jobs ran concurrently across four RTX 4090 GPUs. All 13 result JSONs
have `status=ok`, three expected repeats, matching seeds/settings, and
`data_cache_hit=true`. The batch completed with zero failures; the slowest job
took about 19 minutes. Curves and SHAP were not requested for this all-dataset
performance screen.

# FITCE Class-Reweighting Scope

## Goal

Test whether FITCE should apply class reweighting to every loss term or only to
cross entropy. This is the first all-18-dataset improvement screen after
adopting `importance_scale=train_std`.

The compared scopes are:

- `reweighting_scope=all`: class-balanced aggregation applies to CE, gradient
  alignment, and first-layer-weight alignment. This preserves the preceding
  FITCE behavior and is the CLI default.
- `reweighting_scope=ce`: only CE uses class-balanced aggregation. Gradient
  alignment uses the full batch, and first-layer-weight alignment remains a
  single global term.

The runner now exposes `--reweighting-scope {all,ce}` and records the selected
scope in both result metadata and loss kwargs. An invalid scope is rejected.

## First-Layer-Weight Scope Semantics

The current first-layer-weight distribution is computed directly from global
model parameters as `mean_hidden(abs(W1))`; it has no sample or label axis.
Under `all`, the same global weight loss is explicitly replicated into each
class objective and then class-averaged. Under `ce`, it is included once outside
the class-balanced terms. These code paths match their declared scope, but the
two weight values are algebraically identical with the current global weight
definition.

Producing a numerical scope difference for this term would require defining a
new class-conditional effective-weight attribution rather than merely changing
reweighting scope. That method change is deferred. The present experiment uses
`loss_alpha=1`, hence `weight_scale=0`; it tests only the CE/gradient interaction
and makes no first-layer-weight performance claim.

Unit-level checks confirmed that:

- CE is identical between `all` and `ce` on the same class-imbalanced batch;
- `all` uses the mean of per-class gradient distributions;
- the `ce` gradient term equals the unweighted full-batch gradient term;
- the global weight term follows both scope paths but has the same value;
- omitting the option exactly matches explicit `reweighting_scope=all`;
- the optimized total loss still uses its configured regularization scales.

## Protocol

- Datasets: all 18 real-world datasets.
- Shared FITCE baseline: GPT-5.4 semantic `rank/rank`, class reweighting `on`,
  `importance_scale=train_std`, gradient term only, `REG_SCALE=0.1`, `tau=2`,
  and no warmup.
- `REPEAT=3`, seeds `9803`, `38224`, and `8113`; `PATIENCE=200`,
  `MAX_EPOCHS=5000`, `LR=1e-4`, train batch 256, and eval batch 2048.
- The only experimental change is `reweighting_scope=all -> ce`.
- CE control and old unscaled FITCE results are unchanged from the preceding
  all-dataset screen.

All 18 CE-only jobs ran concurrently across four RTX 4090 GPUs. Every result
has `status=ok`, `data_cache_hit=true`, the expected three seeds, TrainStd
scaling, `reweighting_scope=ce`, and `weight_scale=0`. The batch finished with

# Categorical Feature Encoding

## Goal and Implementation

Compared three categorical-feature representations on all 18 real-world datasets:

- `auto`: preserve each dataset's existing/native representation.
- `integer`: force categorical predictors to integer/ordinal encoding.
- `one_hot`: force categorical predictors to one-hot encoding.

Added `--categorical-encoding {auto,integer,one_hot}` with `auto` as the default. Cache keys distinguish actual representation changes, while native-equivalent settings reuse the existing auto cache. Expanded one-hot columns are mapped back to their original semantic features before applying the GPT-5.4 feature ranking, so FITCE continues to use the same semantic `rank/rank` prior.

## Protocol

- Datasets: all 18 real-world datasets in ACS, WHYSHIFT, and TableShift.
- Methods: CE and the current FITCE (`importance_scale=train_std`, `reg_scale=0.1`, `loss_lambda=1`, `loss_alpha=1`, `weight_scale=0`, `grad_prob_temperature=2`, `reweighting_scope=all`, no warmup).
- Seeds: `9803`, `38224`, `8113`; three repeats.
- Optimizer/training: learning rate `1e-4`, train/eval batch sizes `256/2048`, patience `200`, maximum `5000` epochs, class reweighting enabled.
- Checkpoint validation metrics: balanced accuracy and macro F1.
- ID selection: ID balanced accuracy + ID macro F1.
- OOD selection: OOD mean/worst balanced accuracy + OOD mean/worst macro F1.
- Existing `auto` results were reused; CE and FITCE were run for both forced encodings. All 72 forced-encoding result files passed protocol and completion validation.

Neither forced representation improves the desired ID/OOD balance: integer encoding worsens FITCE relative to CE, while one-hot encoding produces a large OOD loss and the worst all-18 FITCE-vs-CE gap. Retain the CLI option for controlled diagnostics, but do not adopt either forced encoding as the default.

# One-Hot Semantic Expansion Policy

## Motivation and Implementation

The original semantic-to-model expansion copied a semantic feature's complete derived importance weight to every one-hot category. For a semantic feature with weight `w_s` and `k_s` model columns, normalization in FITCE therefore assigned group target mass proportional to `k_s * w_s`, creating a category-cardinality bias.

Added `--semantic-expansion-policy {shared,split}`:

- `shared`: preserve the previous behavior by assigning `w_s` to every category.
- `split`: assign `w_s / k_s` to every category, preserving total semantic-group weight `w_s` after expansion.

For rank priors, the ordinal rank is first converted to the existing importance weight and that weight is then split. Raw rank numbers are never divided. Numerical and unexpanded features have `k_s=1`; model-space rankings do not require semantic expansion. This experiment changes only the target-weight expansion and does not aggregate category gradients.

## Protocol

- Datasets: all 18 real-world datasets, forced `categorical_encoding=one_hot`.
- Comparison: existing one-hot CE and one-hot FITCE `shared` results versus newly run one-hot FITCE `split` results.
- FITCE: GPT-5.4 semantic `rank/rank`, `importance_scale=train_std`, `reg_scale=0.1`, `loss_lambda=1`, `loss_alpha=1`, `weight_scale=0`, `grad_prob_temperature=2`, `reweighting_scope=all`, and no warmup.
- Seeds: `9803`, `38224`, `8113`; three repeats.
- Optimizer/training: learning rate `1e-4`, train/eval batch sizes `256/2048`, patience `200`, maximum `5000` epochs, class reweighting enabled.
- ID selection: ID balanced accuracy + ID macro F1.
- OOD selection: OOD mean/worst balanced accuracy + OOD mean/worst macro F1.
- The 18 split jobs ran with eight workers across four RTX 4090 GPUs and completed in 34.2 minutes with zero failures.

## Decision

Retain `categorical_encoding=auto`; forced one-hot still loses too much OOD selection relative to auto. Adopt `semantic_expansion_policy=split` for active FITCE runs whenever a semantic prior is expanded across multiple one-hot model columns. Under the resulting active auto setup, FITCE is `+0.0002` versus CE on all-18 ID selection and `-0.0022` on OOD selection. Keep `shared` as the backward-compatible CLI behavior for reproducing previous results. Gradient aggregation remains a separate possible follow-up rather than part of this experiment.
