### Conclusion

The full p50/p100/p200/p300/p500 sweep does not show large-patience OOD
degradation. `patience=500` gives the best macro OOD selection score for all
three methods.

If the goal is to report the strongest FITCE setting, `patience=500` is the
most reasonable choice:

- It is FITCE's best absolute score: `2.5359`.
- It gives FITCE the smallest gap to `mlp_ce`: `-0.0363`.
- It shows FITCE benefits most from longer patience: p200 to p500 improves
  FITCE by `+0.0392`, compared with `+0.0097` for `mlp_ce` and `+0.0260` for
  `laat`.

If the goal is to make FITCE look better than LAAT, `patience=100` is the only
macro setting where FITCE is slightly above LAAT, but the margin is only
`+0.0019` and FITCE's own p100 score is much lower than p500. That would be a
weak and likely reviewer-sensitive choice.

Practical recommendation:

- Use `patience=500` for formal FITCE reporting if runtime is acceptable.
- Use `patience=300` only as a faster compromise; it is not the best FITCE
  result and does not improve FITCE's relative position enough to justify using
  it as the main reported setting.

## Ranking Feature Space Option

Goal: add an ablation for whether GPT should see compact semantic features or
every model input feature.

Implemented `--ranking-feature-space {semantic,model}` for both ranking
generation and experiment runners.

Behavior:

- `semantic` is the default and preserves all existing GPT-5.4 artifacts.
- Existing semantic artifact names remain unchanged, for example
  `gpt-5.4_score_all_feature_ranking.json`.
- `model` writes separate artifacts, for example
  `gpt-5.4_score_all_model_feature_ranking.json`.
- If the model feature list is exactly identical to the semantic feature list,
  the code resolves back to `semantic` and reuses the semantic artifact. This
  avoids duplicate API calls and duplicate files for datasets like ACS and
  WHYSHIFT `taxi`.
- If the model feature list differs from the semantic feature list, the code
  requires a model-space artifact.

Supported paths:

- `rank_features.py --ranking-feature-space ...`
- `run_experiment.py --ranking-feature-space ...`
- LLM-prior methods using ranking artifacts:
  - `fitce`
  - `laat`
  - `llm_select`
  - `llm_lasso`

Feature cards:

- TableShift and WHYSHIFT model-space prompts now support encoded model columns.
- Encoded columns are marked as `encoded_model_feature` and describe the source
  semantic feature so GPT can distinguish one-hot/model columns from original
  variables.

Validation:

- `python -m py_compile src/ranking.py src/ranking_generation.py src/feature_cards.py src/benchmark_config.py rank_features.py run_experiment.py`
- `rank_features.py --benchmark acs --dataset acsincome --method score_all --ranking-feature-space model --dry-run`
  resolved to `semantic`.
- `rank_features.py --benchmark tableshift --dataset nhanes_lead --method score_all --ranking-feature-space model --dry-run`
  produced model-space feature cards.
- `run_experiment.py` smoke on ACS/FITCE with `--ranking-feature-space model`
  resolved to `semantic` and successfully loaded existing GPT-5.4 semantic
  weights.
