# 2026-06-08

## TableShift Dataset Integration

- Added a `tableshift` benchmark namespace with eight public TableShift datasets:
  - `college_scorecard`
  - `diabetes_readmission`
  - `nhanes_lead`
  - `nhanes_cholesterol`
  - `anes`
  - `acsfoodstamps`
  - `brfss_diabetes`
  - `brfss_blood_pressure`
- Added `data/tableshift/config.py` for dataset order and official split roles.
- Added `data/tableshift/dataset.py` as an optional-runtime wrapper around the
  official `tableshift.get_dataset(...).get_pandas(split)` API.
- TableShift protocol:
  - official `train` split is used for fitting
  - official `validation` split is used for neural checkpoint / early-stopping
    selection
  - official `id_test` is reported as project `ID`
  - official `ood_test` is reported as project OOD, so `OOD MEAN == OOD WORST`
    and `OOD STD == 0`
  - official `ood_validation` is not used by default
- Default caps:
  - `MAX_TRAIN_VAL_SIZE=10000`, applied to the official `train` split only
  - `MAX_PER_TEST_SIZE=0`, keeping full `id_test` and `ood_test`
- Feature names are taken from TableShift's post-preprocessing pandas columns and
  sorted before tensor conversion. This gives stable feature indices for future
  GPT ranking.
- Ranking-based runners currently use uniform fallback weights/penalties for
  TableShift until dataset-specific ranking artifacts are generated.
- Existing method-centric runners now accept `--benchmark tableshift`.
