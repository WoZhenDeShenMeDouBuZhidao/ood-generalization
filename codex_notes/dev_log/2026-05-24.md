## FeatureImportanceTargetCELoss Suppress Bound Sweep

Goal:

- Decide whether low target feature weights should be set to `0.0` before training.
- A zeroed feature becomes suppressed in `FeatureImportanceTargetCELoss` because the loss treats `raw_feature_weights <= 0.0` as `suppressed_mask`.
- This should activate the existing `suppressed_prob_loss`, weighted by `suppress_scale`, for low-scoring features.

Code prep:

- Added `suppress_bound` to `src.ranking.ranking_to_feature_loss_weights`.
- Added `suppress_bound` to `src.ranking.feature_loss_weights_from_ranking`.
- Added `SUPPRESS_BOUND = float(os.environ.get("SUPPRESS_BOUND", "0.0"))` to every `run_acs*.py`.
- Every ACS runner now passes `suppress_bound=SUPPRESS_BOUND` when building `FEATURE_LOSS_WEIGHTS`.
- Threshold semantics: after the selected ranking/weight mode creates `FEATURE_LOSS_WEIGHTS`, any feature with `weight < SUPPRESS_BOUND` is set to `0.0`; `weight == SUPPRESS_BOUND` is kept.
- `SUPPRESS_BOUND=0.0` is the no-threshold baseline for the sweep.

Current runner defaults before launching:

- `RANKING_METHOD=score_all`
- `FEATURE_WEIGHT_MODE=score`, i.e. `score_all_direct`
- `LOSS_LAMBDA=16.0`
- `LOSS_ALPHA=0.75`
- `grad_scale=12.0`
- `weight_scale=4.0`
- `suppress_scale=1.0`
- `REPEAT=5`

- The run uses the current best ranking/weighting mode, `score_all_direct`, as the default.
